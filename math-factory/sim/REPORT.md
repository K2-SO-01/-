# バランス調整レポート（自動プレイシミュレーション）

`node sim/simulate.js --runs 100 --hours 30` で、正答率 **50% / 70% / 90%** のボットに各100回（合計300回）、最大30時間（実プレイ時間）ずつゲームを遊ばせた結果です。

## ボットの遊び方

- 問題を解く：1問あたり 易30秒・普45秒・難70秒（±30%）。まちがえたらヒントを見てもう一度（成功率は正答率×0.6）、だめなら解説を読む。
  正答率は難易度で変わる（易 +10%、普 ±0、難 −15%）。難易度は本物と同じ自動調整にまかせる。
- 工場：足りない品物の生産ラインを足していく。採掘機→ベルト→コア、採掘機→溶鉱炉→コア、組立機（ベルト給材 or 供給ポート）など。ベルトは最短経路探索で自動配線。電力が足りなければ発電所（石炭が足りなければ石炭ライン）、研究後はソーラー。
- 研究：ロケットに向かう順番で、研究Pがあれば開始。必要な分野の問題を多めに解く（プレイヤーが「解く」ボタンを押すイメージ）。
- 相棒：卵がかえったら得意な設備に配置、防衛が得意な子を戦闘に連れていく。
- 襲撃：来たらすぐ迎え撃つ。カードは「ブロックが必要なら防御、それ以外は攻撃・強化」の優先順位で、本物の問題を正答率どおりに解きながら使う。
- 侵攻ラン：2.5時間後から3時間ごとに1回。HPが減ったら休憩所を優先、それ以外は宝箱→エリート→戦闘。
- ストーリーの特別な行動（復習・模試）もこなす。脱出後は90分間、植民・交易・惑星の防衛も行う。

## 見つかった問題と直したこと

### 1. 終盤が簡単すぎた（ロケット工学の研究が終わった3〜9分後にはクリア）
研究を待つあいだに部品が上限まで積み上がり、ロケットが一瞬で完成していた。研究Pも最大8万も余っていた。
- ロケット部品 10個 → **20個**、組み立て 10秒 → **30秒**、材料を増量（演算チップ3・燃料棒1・レンガ5・歯車4）
- **燃料充填** を追加：部品がそろってから問題に30問正解（「難」は2問ぶん）して打ち上げ。最後のひと押しが「勉強」になる
- 発射台の建設費を5倍、研究所の研究P 8/4秒 → 2/8秒、終盤の研究の研究Pと必要正解数を増やした（ロケット工学：研究P 300→1200、各分野6→9問）

### 2. 襲撃が簡単すぎた（正答率50%でも97%勝てる）
- 敵HPの伸び 7%/回 → **17%/回**（上限2.2倍 → 3.2倍）、強い群れが来るペースを少し早く
- 砲台の援護 4（+2/Lv）→ **2（+1.5/Lv）**
- 結果：正答率で勝率に差がつく（50%:77% / 70%:91% / 90%:97%）＝ちゃんと正解することが防衛につながる

### 3. 侵攻ランのボスがほぼ倒せなかった（2〜10%）
- 紅蓮の女王：HP 120-130 → 95-100、連続攻撃 5×4 → 3×4、強化 筋力+3 → +2
- 休憩所の回復 30% → 35%
- 結果：18〜47%。何度も挑戦して勝てるくらいの強さに

### 4. 正答率90%の人のほうがクリアが遅かった
難しい問題（解くのに時間がかかる）を出されるのに、研究の進み方は問題1問ぶんで同じだったため。
- 研究の必要正解数で **「難」の正解は2問ぶん** に。調整後は正答率によらずクリア時間がそろった（7.3〜7.6時間）

### 5. 進行不能の原因（ボットで見つかり、本体を直したもの）
- **供給ポートの建設費に歯車が入っていて、歯車を作れない状況で詰まる** → 費用を鉄板・銅板に変更
- **鉄の鉱脈がすべて採掘機でうまって溶鉱炉ラインを置けない** → 供給ポートで溶鉱炉に鉱石を送れるようにし、溶鉱炉で溶かす鉱石を選べるようにした
- 4〜5種類の材料が必要な組立機（ロケット部品・演算チップ）にベルトを引ききれない → 「供給ポート」を追加（持ち物から正面の設備へ材料を送る）
- 土地がせまく、中盤でいっぱいになる → 最初の土地 14×10 → **16×12**、開拓で 22×15 → 28×18

### 6. 資源の余り
- 採掘機の速さ 0.4 → 0.25/秒、持ち物の上限（コア300→200、倉庫300→250/台）、組立機・研究所・ソーラー・砲台の建設費を引き上げ
- 研究Pの余りは 4〜8万 → 6千〜1万に。鉱石・製品は上限近くまでたまるが、強化・ガチャ・銀河での植民に使える

## 残っている注意点
- 「詰まり」の残り（300回中19件）は、ボットの配線がうまくいかず必要なラインを置けなかったケース。ゲーム側には「撤去すると全額戻る」「研究は物語と関係なく進められる」「問題を解けば必ず資源が入る」ので、人間のプレイヤーが完全に動けなくなる状況は見つかっていない。
- エラー（例外・不正な値・セーブ破損）は調整前・調整後とも300回中0件。

## 再現方法

```bash
node sim/simulate.js --runs 100 --hours 30 --balance sim/balance-before.json --label 調整前   # 調整前の数値で
node sim/simulate.js --runs 100 --hours 30 --label 調整後                                      # いまの数値で
```
`sim/balance-before.json` は調整前の数値（バランス用の数値をまとめたもの）。`--dump-balance` で今の数値を書き出せる。
